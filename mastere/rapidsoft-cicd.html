Présentation du projet

RapidSoft est un éditeur de logiciels pour les secteurs bancaire et assurantiel (100 collaborateurs, 50 développeurs) confronté à une hausse du trafic malveillant et à des incidents graves révélés via Bug Bounty.

La GAP Analysis du RSSI a mis en évidence trois failles critiques : SDLC sans sécurité intégrée, méconnaissance OWASP des développeurs et absence totale d'automatisation. Ce projet répond en deux missions complémentaires : patch management des dépendances et conformité du pipeline CI/CD.

Mission 1

Patch Management des Dépendances

La face cachée des dépendances

Ce que le développeur déclare

// package.json { "dependencies": { "express": "4.16.0" } } → 1 dépendance déclarée → 0 vulnérabilité visible

Ce qui est réellement installé

// package-lock.json (extrait) accepts · array-flatten · body-parser cookie · debug · depd · destroy ee-first · encodeurl · escape-html finalhandler · fresh · http-errors iconv-lite · inherits · methods mime · negotiator · on-finished parseurl · path-to-regexp · qs · ... → 50+ dépendances transitives → 5 vulnérabilités HIGH cachées

Politique RSSI : le seuil de blocage est fixé à CRITICAL. Les vulnérabilités HIGH génèrent une alerte et déclenchent l'ouverture de Merge Requests Renovate automatiques. MTTR cible : 14 jours sur HIGH, 48h sur CRITICAL.

## Flux DevSecOps — RapidSoft

Développeur
  ↓ git commit (pre-commit hook: linting + gitleaks)
Renovate Bot (scan manifestes · MR auto de patch hebdo)
  ↓ push → pipeline déclenché
Trivy SCA (CVE HIGH,CRITICAL · blocage si CRITICAL)
  ↓
Plumber (audit .gitlab-ci.yml · 6 règles RSSI)
  ↓
Trivy SBOM (CycloneDX → Dependency-Track)
  ↓
GitLab Environment (approbation manuelle → production)

Renovate Bot

Scanne les manifestes, ouvre des MR de patch automatiques avec changelogs. Auto-merge sur les patchs mineurs si les tests passent.

Trivy + SAST

Scan SCA à chaque commit, génération SBOM CycloneDX, vérification des licences GPL/AGPL. Blocage automatique sur CRITICAL.

Plumber

Double rempart de conformité : contrôles CIS+OWASP officiels (88,9 %) + moteur RSSI custom 6 règles RS-001 à RS-006 (6/6).

Mission 2

Conformité CI/CD avec Plumber

Sécuriser le code ne suffit pas si un développeur peut désactiver les contrôles en commentant un job. Plumber audite la structure même du pipeline avant son exécution.

Commenter le scan
# security_sca_scan: # stage: security # script: # - trivy fs .
→ Toutes les CVE passent en prod
Image obsolète
image: node:10-alpine # CVE non patchées # depuis avril 2021
→ Failles connues exploitables
Secrets en clair
script: - export API_KEY="sk_live..." - curl -H "Token: abc123"
→ Credentials leakés dans les logs

Ruleset RSSI — 6 règles de gouvernance

RS-001HIGH
Pas d'images obsolètes
node:10 non patché depuis avril 2021 — RS-001 détecte toute image en fin de vie.
RS-002CRITICAL
Scan SCA obligatoire
Analyse Trivy systématique des dépendances — aucun pipeline sans SCA.
RS-003MEDIUM
Versions pinnées
Pas de tag :latest — builds reproductibles et traçables.
RS-004CRITICAL
Pas de secrets en clair
CI/CD Variables masquées obligatoires — blocage immédiat si credential détecté.
RS-005HIGH
SAST activé
Analyse statique du code source — template GitLab natif inclus.
RS-006LOW
Artifacts archivés 90 jours
Traçabilité pour audit ISO 27001 — rapport RSSI et SBOM conservés.
